## Какво прави модулът

Пренася формулния механизъм от BoM редовете (`mrp_bom_line_formula_template`)
върху **операциите** на BoM-а. На всяка операция (`mrp.routing.workcenter`)
може да се закачи шаблон с Python формула, която при създаване/потвърждаване
на производствена поръчка (MO) контролира:

1. **Продължителността** на workorder-а (в минути);
2. **Дали операцията изобщо да я има** в тази поръчка (`skip`);
3. **Кои суровини се консумират** в този workorder.

Инсталира се **ръчно** — само на бази, които реално ползват операции/работни
поръчки. Без формула модулът не променя нищо (no-op).

## Как се ползва

1. *Производство → Конфигурация → Formula Templates* — създай шаблон
   (същата библиотека като за BoM редовете);
2. Отвори операцията в BoM-а → секция **Operation Formula** → избери шаблона;
3. Формулата се изпълнява за всяко MO при потвърждаване.

## Изходни променливи (какво записва формулата)

| Променлива | Ефект |
|---|---|
| `result` (или `duration`) | очаквана продължителност в минути |
| `skip = True` | workorder-ът се маха изцяло от MO-то (суровините му се освобождават) |
| `collect_materials = True` | всички още незакачени raw move-ове се консумират в този workorder |
| `materials = [продукти]` | move-овете само на тези продукти се консумират тук |

`duration` влиза **инициализирана със стандартната стойност** (изчислената от
Odoo по time_cycle и т.н.) — затова работят релативни корекции:

```python
result = duration * 1.2          # +20% върху стандарта
```

## Входен контекст (какво вижда формулата)

| Променлива | Какво е |
|---|---|
| `operation` | операцията (`mrp.routing.workcenter`) |
| `workcenter` | работният център |
| `production` | производствената поръчка (`mrp.production`) |
| `workorder` | работната поръчка (или `False` преди създаването ѝ) |
| `product` | произвежданият продукт |
| `product_qty` | количеството на MO-то |
| `duration` | стандартната продължителност (начална стойност) |
| `env` | Odoo environment — `env.ref(...)`, search-ове |
| `width`, `height`, … | design параметрите на произвеждания лот, когато `mrp_design_matrix` е инсталиран (T3 интеграция) + целият `design_context` dict |

## Примери

**Време от площта (design matrix):**
```python
result = 10 + (width * height / 1e6) * 2.5
```

**Условна операция** — лакиране само при поръчано покритие:
```python
skip = not has_coating
result = duration
```

**Операцията консумира конкретни материали:**
```python
result = 20
materials = [env.ref('my_module.product_glue'),
             env.ref('my_module.product_screws')]
```

**Първата операция събира всички суровини** (като T3 в матрицата):
```python
result = duration
collect_materials = True
```

## Поведение при грешка

Изключение във формулата или нечислов резултат → **warning в лога** и
стандартното поведение (стандартна продължителност, операцията остава,
материалите не се пипат). Формула с грешка никога не чупи MO-то.

## Технически бележки

- Hook-ове: `mrp.workorder._get_duration_expected()` (продължителност) и
  post-pass в `mrp.production.action_confirm()` (skip + материали);
- Закачането на материали изисква `stock.move.workorder_id` (наличен в
  core mrp) — пазен с проверка по `_fields`;
- v18: `lot_producing_id` / v19+: `lot_producing_ids` — кодът ги детектира
  автоматично, един и същ е на 18/19/20;
- Манифестът остава `license: AGPL-3` (Odoo няма "dual" стойност) —
  комерсиалната оферта е в header-ите и root документите.
