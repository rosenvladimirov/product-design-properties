# ADR-0006: Пренаписване на формулното evaluation ядро (махане на чуждата AGPL котва)

- **Статус:** приет
- **Дата на решението:** 2026-06-11
- **Дата на записа:** 2026-07-13 (консолидация)
- **Взето от:** Росен Владимиров
- **Източник на реконструкцията:** memory `products/design_matrix/project_formula_eval_cleanroom_2026_06_11`, `topics/licensing/licensing_master_reference` §7; git `product-design-properties` `3c05d2b` (2026-06-11), `manufacture` `9c66bbe7`/`f73f6f94` (2026-06-11, „[REM] drop mrp_bom_line_formula_quantity (third-party Aion Tech)")

## Контекст

Формулният стек (изчисляване на количествата през `safe_eval`) зависеше от чужд модул `mrp_bom_line_formula_quantity` (Simone Rubino / Aion Tech), лицензиран **AGPL-3**. Тази зависимост беше пречка за dual-licensing на Matrix стека: AGPL заразява надолу по `depends` веригата и блокира проприетарния пласт.

## Разгледани алтернативи

1. **Оставане на Aion модула.** — Отхвърлено: несъвместимо с dual-licensing ([ADR-0007](0007-dual-licensing.md)).
2. **Строг двуекипен clean-room** (екип А пише спец, екип Б имплементира без достъп до оригинала). — НЕ е приложен (виж „Произход").
3. **Пренаписване на ядрото без копиране на код.** — Прието.

## Решение

Написано е **собствено** формулно ядро в `mrp_bom_line_formula_template`: `_quantity_formula_values` (базов context builder), собствен hook `mrp.production._get_move_raw_values`, собствени BoM view-та. Aion headers сменени; `mrp_bom_line_formula_quantity` **премахнат** от всички `depends` (18.0/19.0/20.0, потвърдено 0 съвпадения); архивиран извън репото. Тестовете re-enabled + нов `test_move_generation.py`. Merges: 18.0 `3c05d2b`, 19.0 `4004ba9`, 20.0 `36b1698`.

## Обосновка

Махането на чуждата AGPL котва е предпоставка за проприетарния пласт на dual-licensing. Собственото ядро прави формулния стек изцяло контролируем от правоносителя.

## Последици

- Отпадна външната AGPL зависимост → dual-licensing стана възможен ([ADR-0007](0007-dual-licensing.md)).
- Върху собственото ядро по-късно стъпиха: `skip=True` (условни редове), `mrp_operation_formula_template`, employee инжекция, `mrp_bom_line_formula_forced_lot`.
