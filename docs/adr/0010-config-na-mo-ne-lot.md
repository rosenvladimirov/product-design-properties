# ADR-0010: Конфигурацията на матрицата живее на MO, не на партидата (`mrp_design_matrix_production`)

- **Статус:** приет (19.0 pushed; 18/20 порт локален, runtime-untested)
- **Дата на решението:** 2026-07-06
- **Дата на записа:** 2026-07-13 (консолидация)
- **Взето от:** Росен Владимиров (изрично искане)
- **Източник на реконструкцията:** memory `clients/mec/project_mec_pcb_options_matrix_2026_07_03` (раздел „НОВ МОДУЛ mrp_design_matrix_production"); git `product-design-properties` 19.0 `39a581e` (engine 3.10.0), `967b8aa` (модул 1.0.0)

## Контекст

Дизайн контекстът (variant/параметри) досега се четеше от партидата (`stock.lot`). Но при производство конфигурацията трябва да пътува с производствената поръчка (MO) — при backorder/split/merge, надолу по полуфабрикатите — и да контролира партидата, не обратното. Не всеки продукт е партиден.

## Разгледани алтернативи

1. **Конфиг само на партидата** (`stock.lot.design_params`). — Отхвърлено: не работи за непартидни продукти; не пътува при split/backorder; партидата не е естественият носител на производствено намерение.
2. **Конфиг на MO-то** (огледало на партидата), с dual-read MO→lot fallback. — Прието.

## Решение

Нов модул `mrp_design_matrix_production`: MO Properties (copy=True → split/backorder пренасят конфига безплатно); merge hook блокира различен конфиг / пренася; `_post_run_manufacture` down-prop надолу по полуфабрикатите; `button_mark_done` инжектира **отпечатък** (четим блок в `note` + къс sha1 в `ref`) в описанието на партидата. **Engine рефактор** (`mrp_design_matrix` 3.10.0): `design.param.definition._build_context(params, extra)` = ЕДИНСТВЕН резолвер (`stock.lot` става тънка обвивка); `mrp.production._resolve_design_context()` overridable (default = партида) — точката, през която конфигът се мести на MO.

## Обосновка

Производственото намерение принадлежи на MO-то, не на партидата. Единственият резолвер (`_build_context`) премахва дублирането lot/MO и прави източника на контекста сменяем (overridable). Отпечатъкът в партидата дава четима, verify-ируема следа какво е произведено.

## Последици

- Конфиг пътува през целия производствен жизнен цикъл (split/backorder/merge/полуфабрикати).
- Непартидни продукти вече поддържани.
- ⚠️ **Lockstep 18/20 = ОТДЕЛЕН ПОРТ, не копие** — engine-ите са дивергирали (18.0 има съвсем различен, по-опростен резолвер); 18/20 версиите са локални и **runtime-untested** (няма 18/20 инстанция).
